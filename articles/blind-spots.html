Blind Spots

In early 2024, GitLab integrated Duo, an AI assistant, directly into developer workflows. The feature was widely adopted, but suddenly, response times crawled to a halt. Developers stared at spinning loading icons. When the engineering team checked their standard dashboards, everything looked green—CPU utilization was nominal, memory was stable, and the pods were running. The system was technically "up," but the AI was functionally down.

What happened wasn't a server crash. The AI model was caught in a silent retry loop. When the underlying LLM provider failed to return a satisfactory payload, the agent automatically retried the request. These retries compounded, eventually triggering external rate limits and cascading into a full-scale degradation of service. Traditional monitors saw a healthy endpoint; the reality was an agent drowning in its own automated persistence.

The Agent's Ghost

Stop monitoring your LLMs like web servers. Agents don't crash; they hallucinate, loop, and confidently fail. Standard application performance monitoring (APM) is fundamentally blind to this. We have spent a decade optimizing for the four golden signals—latency, traffic, errors, and saturation. But an agent returning a perfectly formatted, 200 OK JSON response that confidently instructs a user to violate a refund policy is a catastrophic failure, not a success.

When Klarna deployed their AI customer service assistant, it handled millions of chats with speed that radically reduced resolution times. By standard metrics, it was a triumph. But beneath the surface, the agent was hallucinating edge-case policies. Because the observability stack only tracked throughput and duration, the semantic failures went unnoticed until human agents had to clean up the mess. We are building autonomous reasoning engines and evaluating them with dashboards designed for stateless web servers. It is like checking a car's engine oil while the driver steers off a cliff.

Infra Metrics Payload Tracing Semantic Evals

Connecting The Dots

The missing link in AI platform architecture is behavioral observability. You cannot debug a reasoning loop with a latency percentile. When GitLab Duo choked on retry storms, the team had to implement deep OpenTelemetry tracing that followed the payload—not the network request—through the Ruby backend, into the Vertex AI call, and back. They had to observe the agent's actions, not just the server's state.

A 200 OK is meaningless if the model is confidently lying.

To build reliable AI, we must fuse our infrastructure traces with semantic evaluations. This means logging the actual prompt inputs, the chain-of-thought outputs, and running automated evals against them in real-time. The systems-thinking methodology at play here shifts from simple SRE error budgets to quality budgets. You aren't just tracking how often the endpoint fails; you are tracking how often the agent's reasoning falls below an acceptable threshold.

Credibility And Caveats

The GitLab postmortem proves that without payload-level distributed tracing, AI agents will silently fail until they hit a hard infrastructure limit. Klarna's experience proves that optimizing for speed without semantic accuracy creates technical debt at the customer support layer. The methodology required is defense-in-depth applied to reasoning: tracing the infrastructure, evaluating the output, and enforcing idempotency so an agent doesn't trigger a refund loop three times.

The strongest counterargument is cost: "Running automated evaluations and logging full payloads on every request is too expensive and slow." But this ignores the power of shadow sampling. You can route 5% of traffic to an asynchronous evaluation pipeline using a fast, cheap model like Groq, catching hallucinations without adding latency to the user experience.

Recall Practice: Why did GitLab Duo's standard monitoring fail to catch the retry storm?
Answer: Standard monitors tracked pod health and network latency, but not the semantic payload loop. The endpoint returned 200 OKs while the agent silently retried LLM calls.
Recall Practice: What is the counterargument to real-time LLM evals, and how is it solved?
Answer: Cost and latency. Solved via shadow sampling (e.g., 5% of traffic) to an asynchronous pipeline using fast models like Groq.

Taking The Reins

You cannot afford blind spots in autonomous systems. First, implement a proxy layer for all LLM calls. Tools like Helicone or LangSmith allow you to inject a lightweight proxy that captures every prompt and completion without refactoring your core application. Second, stop treating prompts as static strings. Version control your prompts and tag your traces with the specific prompt version, just as GitLab tags releases. Third, establish quality budgets. If your LLM eval scores drop below a threshold, circuit break the agent and fall back to a deterministic flow.

Open Your Eyes

The era of treating AI as a simple API call is over. Route one LLM endpoint through a tracing proxy today, look inside the payload, and find the hallucinations hiding behind your 200 OKs.
