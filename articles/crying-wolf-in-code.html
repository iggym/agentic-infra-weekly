Crying Wolf in Code

The Green Board Blues

In early 2026, Indeed's engineering team was staring at a perfectly green Datadog dashboard. Latency was low, error rates were zero, and HTTP 200s were flowing steadily. Yet, user complaints were skyrocketing. Their AI-generated job summaries were completely broken—hallucinating fake titles, outputting empty strings, or abruptly truncating mid-sentence. The infrastructure was perfectly healthy; the product was failing.

Across the industry, Cursor IDE was fighting its own phantom menace. Their AI code completions slowed to a crawl. Grafana dashboards flashed red, showing GPU utilization on their inference cluster maxed out. Engineers scaled up vLLM instances, throwing more compute at the problem. It took days to realize the GPUs weren't underpowered; a Redis cache eviction policy was dropping prompt prefixes, forcing the models to recompute contexts repeatedly.

Both teams were blind not because they lacked data, but because their alerts were screaming about the wrong things.

Mind the Water

AI observability alerts on the wrong signal because we measure plumbing instead of water quality. We monitor GPU utilization, HTTP status codes, and token counts, completely missing semantic drift and structural failure.

Traditional observability assumes deterministic transformations: if the server responds fast and with a 200, the job is done. LLMs are non-deterministic compilers. A 200 OK only means the server finished talking, not that it made sense.

Pipes and Prisms

We treat LLMs like microservices, but they are closer to dynamic compilers with a 5% baseline hallucination rate. The SRE Four Golden Signals—latency, traffic, errors, saturation—break down when the "error" is a perfectly formatted JSON object containing a disastrous hallucination.

Indeed's Datadog setup was tracking infrastructure health, completely blind to semantic quality. Cursor's Grafana dashboards tracked resource saturation, but missed the cache layer's actual hit ratio.

A 200 OK is just the server saying it finished talking, not that it made sense.

We need to connect the plumbing of SRE with the prisms of ML evaluation. Tools like Helicone act as a transparent proxy, intercepting the water flow to test for lead. Langfuse stitches together the trace, linking the user's prompt to the model's output and the GPU's latency. Phoenix visualizes the semantic drift over time.

What are the SRE Four Golden Signals?

Latency, traffic, errors, saturation. (But they miss semantic quality!)

The Empty Room

The strongest counterargument: "Infrastructure monitoring is the foundation; you need it first." True, but a foundation isn't a roof. Treating infra health as feature health gives false confidence. You can have zero 502 errors and still ship a broken product.

The systems-thinking methodology at work here is a failure of error budgets. Indeed had no error budget for "hallucinated job titles" because they only budgeted for latency and HTTP 500s. They applied SRE principles to the network layer while leaving the semantic layer completely unmonitored.

Shift the Focus

If your alerts are firing on CPU spikes but ignoring semantic drift, you are driving blind. Here are three high-leverage actions to fix it:

1. Add a Semantic Validator to Your Proxy: Route your LLM calls through a proxy like Helicone. Use a fast, cheap model (like Groq's Llama 3) as an LLM-as-judge to flag outputs that deviate from expected schemas or tones.

2. Track Output Distribution Drift: Don't just log tokens. Use tools like Phoenix to calculate embeddings of your outputs over time. If the semantic distance between yesterday's outputs and today's outputs spikes, trigger an alert.

3. Implement Quality Circuit Breakers: Instead of retrying on a 500, retry when the output fails a semantic check. Link this to Langfuse traces so you can see exactly which prompt configuration caused the drift.

Check Your Output

Stop alerting on plumbing. Pick your most-used AI feature, write a single regex or LLM-as-judge check for its worst failure mode, and wire it to a Slack alert today.
